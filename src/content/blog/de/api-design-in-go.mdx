## Prinzipien vor Frameworks

Frameworks kommen und gehen. Die Prinzipien guten API-Designs sind zeitlos.

### 1. Explizite Fehlerbehandlung

Gos Error-as-Value-Muster ist kein Bug -- es ist das Feature. Verstecke Fehler nicht hinter Middleware-Magie.

```go
type APIError struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
    Detail  string `json:"detail,omitempty"`
}

func (e *APIError) Error() string { return e.Message }

func respond(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    json.NewEncoder(w).Encode(v)
}
```

### 2. Versionierung durch Content Negotiation

URL-Versionierung (`/v1/users`) ist ein Anti-Pattern. Nutze `Accept`-Header stattdessen. Deine API-Oberflache andert sich langsamer als du denkst.

### 3. Idempotenz-Schlussel

Wenn deine API Zustand andert und ein Client wiederholen konnte, brauchst du Idempotenz. Eine UUID, die als `Idempotency-Key`-Header gesendet und mit der Antwort gespeichert wird, kostet wenig und verhindert ganze Klassen von Fehlern.
